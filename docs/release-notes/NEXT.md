## 一句话

**你现在可以把这台手机当成一台 OpenAI 兼容的私有 AI 服务器**：模型跑在本地、**数据不出设备**，
同机 App 或同 WiFi 的设备都能用标准 API 调用它。而且它**默认最安全、够克制、能扛住后台被杀**。

---

## 新功能

### 🖥️ 服务器模式（把手机当推理服务器）

- 内置 `llama-server` 原生支持 OpenAI 接口：`/v1/chat/completions`、`/v1/models`、
  `/v1/completions`、`/v1/embeddings`、`/health`。
- 服务器监听参数全部可配：**绑定范围**（仅本机 `127.0.0.1` / 局域网 `0.0.0.0`）、**端口**
  （默认 `18787`）、**并发槽数**（`-np`，`1–4`）、**API Key**。
- **默认关闭（opt-in）**：不开服务器模式时，引擎行为与以往**逐字节一致**——只绑 `127.0.0.1`、
  端口 `18787`、单槽、不鉴权。老用户升级**零感知、零风险**。
- **默认安全**：局域网绑定会**强制/自动生成 API Key**（同 WiFi 裸奔等于把手机算力与电量敞开门）。

### 🧭 独立的「本地推理服务器」二级页

- 过去服务器配置藏在「本地模型」页里，用户反馈"藏得太深"。现在它**单独成页**：
  **设置 → 本地推理服务器**，一眼可见状态、连接设置、接入方式、能力边界与安全提示。
- 提供**可直接复制**的本机 / 局域网 `base_url`、一行自检命令
  `curl -s http://127.0.0.1:18787/v1/models`。

### 🧮 槽位优化

- 并发槽数可在 `1–4` 之间选择；单槽时页面会**主动提示**「第二个客户端会排队」，并提供
  **一键升到 2 槽**。
- 同时**如实告知代价**：`-np 4` **不等于** 4 倍吞吐——多槽会按槽数倍增 KV 内存、降低单流速度。
  个人使用建议 `1`。

### 🌡️ 热断路器（高温自动暂停 / 降温自动恢复）

- 服务器模式是**持续负载**（模型常驻 + 请求随时进来），比聊天更容易过热。因此新增**热断路器**：
  - SoC 温度 **> 85°C** → 自动卸载模型**止热**；
  - 降至 **< 70°C** → 用上次的模型**自动恢复**；
  - 两个阈值之间留 **15°C 死区**（迟滞），避免阈值附近反复开关引擎。
- **温度读不到时不暂停**（宁可不保护，也不因探测异常误停服务）。
- 阈值可在设置页调整；实时温度与断路器状态可见。

### 🔋 保活加固（后台存活）

- **无 root 也能用**：
  - **前台服务 + 常驻通知**：「微玄推理服务器运行中 · host:port」，防冻结 / 防回收；
  - **克制的唤醒锁**：只在「服务器模式开启 + 引擎已加载」时持有，引擎停止**立即释放**，
    且带 1 小时超时自动到期——**不做无条件 24/7 持锁**（那会持续耗电发热）；
  - **轻量看门狗**：被系统杀掉但服务器模式仍开着 → **自动拉起**（指数退避），
    **连续失败 5 次后停止重试并通知你**。
- **有 root 才多做的事**（失败静默降级，不影响功能）：
  - 把 App 与 `llama-server` 子进程的 `oom_score_adj` 调到 **-800**（降低被 LMK 杀的概率）；
  - 加入 Doze / 电池优化白名单；
  - 内核 wakelock 兜底持续唤醒。
- **设置页新增「保活（后台存活）」分节**：显示前台服务 / 唤醒锁 / 看门狗是否活跃、已自动拉起几次、
  root 加固是否施加；提供**一键打开「关闭电池优化」**，并说明**小米 / 澎湃（HyperOS）需手动设置**的
  自启动白名单与省电策略。

## 已知限制（如实告知）

- `-np 4` ≠ 4 倍吞吐；4B 量化模型单流约 **9–17 tok/s**，随上下文长度与设备状态波动。
- llama.cpp 不是高并发后端：**适合个人 / 低频调用**，不适合多人高强度同时调用或需要稳定 QPS 的负载。
- 冷启动需加载模型（数秒~数十秒）；长 prompt 的 prefill 也需时间。
- **热断路器暂停期间**，客户端会看到连接被拒 / `503`，降温恢复后**重试即可**成功。
- **厂商省电策略（小米 / 澎湃等）无法由应用自动修改**，需按设置页提示手动添加自启动白名单、
  关闭电池优化。
- `AndroidManifest.xml` 目前**未声明 `android.permission.WAKE_LOCK`**：App 内的
  `PartialWakeLock` 会被系统拒绝（代码已静默降级），无 root 的持续唤醒暂由**前台服务**承担；
  补上该权限后唤醒锁即自动生效（无需改代码）。

## 升级与兼容

- **升级用户默认零感知**：服务器模式默认关闭，所有新增保活行为**只在服务器模式开启时生效**；
  未开启服务器的用户**不写新键、不起新服务、不持锁**，行为与旧版本一致。
- 不引入任何新的用户可见偏好键（保活完全跟随服务器模式开关）。
